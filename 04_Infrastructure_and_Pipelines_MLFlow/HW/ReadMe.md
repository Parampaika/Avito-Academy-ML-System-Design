# Отчет по экспериментам MLflow

Эксперименты проводились последовательно в 4-х разрезах:

### Шаг 1: Выбор способа кодирования категорий

В качестве базовой модели использовалась логистическая регрессия. 

* `OrdinalEncoder` — показал худший результат (ROC-AUC: 0.8509)
* `TargetEncoder` — средний результат (ROC-AUC: 0.8980)
* `OneHotEncoder` — лучший результат (ROC-AUC: 0.9014). Был зафиксирован для дальнейших шагов.

### Шаг 2: Выбор типа алгоритма

При зафиксированном `OneHotEncoder` мы сравнили 3 различных архитектуры:

* `DecisionTree` (ROC-AUC: 0.8903)
* `LogisticRegression` (ROC-AUC: 0.9013)
* `RandomForest` (ROC-AUC: 0.9108). Случайный лес показал лучшую обобщающую способность и был выбран для тюнинга.

### Шаг 3: Тюнинг гиперпараметров

Для `RandomForest` была запущена сетка (GridSearch) из 18 комбинаций параметров: `n_estimators` (50, 100, 200), `max_depth` (10, 20, None) и `min_samples_split` (2, 5).

* Было замечено, что деревья без ограничения глубины (`max_depth=None`) переобучаются и показывают качество хуже (~0.9015).
* Лучшая комбинация: `n_estimators=200`, `max_depth=20`, `min_samples_split=5`. Метрика ROC-AUC выросла до 0.9138.

### Шаг 4: Зависимость качества от объема данных

Как объем обучающей выборки влияет на лучшую модель. Данные "скармливались" порциями (тестовая выборка оставалась неизменной):

* 1% данных: ROC-AUC 0.8835
* 10% данных: ROC-AUC 0.8974
* 50% данных: ROC-AUC 0.9101
* 100% данных: ROC-AUC 0.9138
  
Вывод: Метрика логарифмически растет вместе с объемом данных. Сбор дополнительных данных мог бы еще немного улучшить модель, но плато близко.


## Итог: Лучшая модель

* Предобработка: `OneHotEncoder` + `StandardScaler`
* Модель: `RandomForestClassifier(n_estimators=200, max_depth=20, min_samples_split=5)`
* Метрики на тесте: ROC-AUC: 0.9138 | Accuracy: 0.8596
* Код именно этой модели (и проверка её выгрузки из MLflow Registry) оставлен в финальном ноутбуке, воспроизводимость подтверждена.
